# 薄肌 · 训练饮食记录 App 开发计划

## 0. Context

`D:\lian` 是空目录。这份是动手前的设计文档，已按你的批注修改。

**产品定位**：只用来训练薄肌，不支持减重目标。App 只起辅助作用：
- 不生成训练计划，只支持导入，鼓励你先和自己的 AI 讨论好计划再导入
- 不在 App 里分析数据，导出后交给你自己的 AI 分析

**不打扰原则**（贯穿全 App，优先级高于其他所有设计）：
- 不发通知，不用闹钟
- 不显示倒计时、计时器
- 不做连续打卡天数、完成率、红色警示
- 不显示缺口，不弹提示
- 没完成的项目保持中性外观，不强调"未完成"
- 唯一的提示是加重标记，做得极小，不显示数字

## 3. 页面设计

### 3.1 主页

- **核心区**：上面"摄入"、下面"消耗"两个大数字，中间一条细线。数字逐位滚动，消耗每秒更新一次（页面可见时才计时，回到前台时按当前时间重新计算）。**不显示缺口**
- **背景文字**：页面中央很淡地写着"训练日"或"休息日"，颜色接近背景，作为底纹
- **两个按钮**：「日记」「体重」，样式和权重相同，点击分别进入独立页面
  - **日记页**：按日期列出，今天的条目在最上面，点开直接书写，自动保存
  - **体重页**：顶部是数字输入（同一天重复输入会覆盖），下方是体重曲线
    - 默认显示全部数据，可以双指缩放、拖动
    - 曲线自动平滑：对每日体重做指数滑动平均，再用单调三次样条画线
    - 原始数据用淡灰点表示
- **没有概览卡片**

**导出**（左上角）：底部弹出三个选项
1. 全部
2. 自上次导出起（显示上次导出日期）
3. 日期范围

详见 §6.3。

### 3.2 训练页

**顶部**：只显示日期，格式 `10/11`。

**打卡按钮**：
- 出现条件：今天是训练日，当前时间 ≥ 4:00，今天还没打卡
- 外观：缓慢呼吸的圆形按钮"开始"
- 按下后重震动一次，按钮淡出消失。**不显示计时器**
- 没打卡直接点了第一组：自动记一条开始时间，按钮同样淡出

**动作列表**：
```
[卧推图标]  卧推                     ( 2/4 )
            60kg × 8 · ●●○○
```
- 左边是图标，按动作名称自动匹配，见 §7
- 右边是圆形按钮，点一次完成一组：轻震动，圆点填满，数字 +1
- 一个动作全部完成：中等震动，整行变灰，名字上划一条细线
- 长按按钮撤销一组
- **加重标记**：上次这个动作所有组都做到了次数区间的上限，就在重量后面加一个很小的灰色 `↑`（和次要文字同色、同字号）。不显示数字，不弹提示，加多少由你自己决定

**今天全部完成**：全天完成的震动节奏，训练自动记为结束。**不需要结束按钮**，也不做庆祝动画，整页安静地变成完成状态。

**点开动作**：底部弹出编辑面板
- 加减按钮调当前重量（步进 2.5kg）和次数，只影响之后的组
- 一条迷你折线，显示最近几次训练每次的最大重量

**加练按钮**：列表底部一个低调的 `＋ 加练`
- 打开一个自然语言输入框，例如"跑步 30 分钟""今天走了 8000 步"
- 步数也在这里记
- **不计入消耗**，只存文字和时间，导出时带上

**休息日**：页面只有日期、背景淡字"休息日"和"＋ 加练"，没有任何引导。

### 3.3 饮食页

**顶部**：三条横向**条形**，从上到下是蛋白、碳水、脂肪
- 条形左边是名称，右边是 `已摄入 / 目标 g`
- 条形下面一行小字显示总热量
- 超过目标时条形保持满格，**不变色，不警示**

**饮食任务**：
```
[蛋图标]   练前鸡蛋   2 个                ○
[牛奶图标] 奶昔       1 份                ○
```
- 打勾：轻震动，勾是一笔画出来的动画，这一项的营养素平滑加进顶部条形
- 再点一次取消打勾，条形回缩
- 打勾时存一份营养数据快照，之后修改或重新导入计划，历史数据不变

**加餐按钮**：底部 `＋ 加餐`，比如临时在 711 买了个鸡蛋
- 自然语言输入，例如"711 茶叶蛋一个"
- **不计入摄入**，只存文字和时间，导出时带上

### 3.4 个人页

- 头像、身高、体重（最新一次记录）、性别、年龄
- **年龄**：只让你填一个数字，后台同时记下填写的年份。之后每年 1 月 1 日自动加一，计算方式为 `当前年龄 = 填写年龄 + (今年 − 填写年份)`
- 营养目标：来自饮食计划导入，也可以手动修改
- 设置：只有震动强度（关 / 弱 / 标准 / 强）
- 数据管理：从备份恢复、清空数据（需要二次确认）
- **主题**：跟随系统的明暗模式，没有设置项

## 4. 热量计算

所有计算放在纯 Kotlin 的 `CalorieEngine` 里，可以直接写单元测试。一天按自然日 00:00 切分；4:00 只是打卡按钮出现的时间。

**摄入** = 已打勾饮食项的快照热量之和。加餐不计入。

**消耗**：
```
BMR（Mifflin-St Jeor）
  男：10×体重 + 6.25×身高 − 5×年龄 + 5
  女：10×体重 + 6.25×身高 − 5×年龄 − 161

日均匀消耗 = BMR × 1.2 + 日常活动总热量（导入，可以为 0）
此刻均匀消耗 = 日均匀消耗 × (今天已过秒数 / 当天总秒数)

训练消耗 = Σ 已完成组数 × 该动作的 kcalPerSet（导入）

总消耗 = 此刻均匀消耗 + 训练消耗
```
- 日常活动比如"走路去教室"，导入时以天为单位填热量，和基础代谢一样按时间均匀加到消耗上
- 训练消耗每完成一组就加上，撤销一组就减掉
- 加练不计入
- 体重取当天或之前最近一次记录

## 5. 数据模型（Room）

通用规则：
- 主键用 UUID 字符串，所有表带 `updatedAt`，增量导出时用
- 日期存 epochDay
- 模板类的表用 `archived` 软删除，替换导入后历史日志还能找到原来的模板

| 表 | 主要字段 |
|---|---|
| Profile | 身高、性别、填写年龄、填写年份、头像路径 |
| WeightLog | 日期（唯一）、体重 |
| Diary | 日期（唯一）、内容 |
| TrainingPlan | 名称、days、排序、archived |
| Exercise | planId、名称、组数、repsMin、repsMax、kcalPerSet、当前重量、当前次数、排序、archived |
| SetLog | exerciseId、动作名快照、日期、时间戳、重量、次数、kcal 快照 |
| TrainingSession | 日期、planId、开始时间、完成时间（可空） |
| DailyActivity | 名称、每日 kcal、archived |
| MealTask | 名称、数量、单位、蛋白、碳水、脂肪、kcal、排序、archived |
| MealLog | mealTaskId、日期、时间戳、名称和营养数据快照 |
| FreeLog | 日期、时间戳、类型（加练 / 加餐）、原文 |
| ExportRecord | 时间、范围类型、起止日期 |

图标不存数据库，显示时按名称实时匹配。

## 6. 导入 / 导出

### 6.1 通用信封
```json
{ "app": "baoji", "type": "training", "version": 1, ... }
```
`type` 有三种：`training`、`diet`、`backup`。

### 6.2 导入格式

**训练计划**：
```json
{
  "app": "baoji", "type": "training", "version": 1,
  "daily": [
    { "name": "步行去教室", "kcal": 120 }
  ],
  "plans": [
    {
      "name": "上肢 A",
      "days": [1, 4],
      "exercises": [
        { "name": "卧推", "sets": 4, "reps": [6, 8], "weight": 60, "kcalPerSet": 8 },
        { "name": "高位下拉", "sets": 4, "reps": [8, 10], "weight": 50, "kcalPerSet": 7 }
      ]
    }
  ]
}
```
- `daily` 可以省略或为空数组，`kcal` 可以为 0
- `kcalPerSet` 必填，可以为 0
- `reps` 可以写成区间 `[6, 8]` 或单个数字 `8`
- `days` 用 1–7 表示周一到周日
- 不需要 `icon` 字段

**饮食计划**：
```json
{
  "app": "baoji", "type": "diet", "version": 1,
  "targets": { "protein": 170, "carbs": 150, "fat": 50 },
  "meals": [
    { "name": "练前鸡蛋", "amount": 2, "unit": "个", "protein": 12, "carbs": 1, "fat": 10 },
    { "name": "奶昔", "amount": 1, "unit": "份", "protein": 79, "carbs": 48, "fat": 7 }
  ]
}
```
- `amount`、`unit`、`protein`、`carbs`、`fat` 必填，营养素是这一项总量的克数
- `kcal` 可选，不填时按 `4×蛋白 + 4×碳水 + 9×脂肪` 计算

**导入流程**：
1. 粘贴 JSON 或从文件选择
2. 实时校验并标出出错的行：先用 `parseToJsonElement` 检查语法，把字符偏移换算成行号；再逐字段检查，报出类似"第 7 行 kcalPerSet 缺失"的提示
3. 预览将导入的内容
4. 选择替换或合并
   - **合并**：按名称匹配，同名的更新，新的新增
   - **替换**：旧模板全部归档，再写入新的
   - 整个过程在一个事务里完成，失败就整体回滚

### 6.3 导出

- 三种范围：全部 / 自上次导出起（按 `updatedAt` 筛选）/ 日期范围
- 导出内容：个人资料、体重、日记、训练组记录、打卡记录、饮食记录、**加练和加餐的原文**、当前计划和目标
- 为了方便你的 AI 分析，导出的 JSON 按日期分组：
  ```json
  { "days": [ { "date": "2026-10-11", "weight": 62.1, "diary": "…", "sets": [...], "meals": [...], "free": [...], "kcalIn": 1780, "kcalOut": 2350 } ] }
  ```
- 保存方式：系统文件选择器保存，或者分享出去。文件名为 `baoji-2026-10-11.json`
- **从备份恢复**：个人页 → 数据管理，选择一个全量导出的文件 → 确认后覆盖全部数据

## 7. 视觉与动效

**配色**：苹果系统的黑白灰，不用任何彩色。

| 用途 | 浅色 | 深色 |
|---|---|---|
| 背景 | #F2F2F7 | #000000 |
| 卡片 | #FFFFFF | #1C1C1E |
| 次级填充（条形底色等） | #E5E5EA | #2C2C2E |
| 分割线 | #C6C6C8 | #38383A |
| 次要文字 | #8E8E93 | #8E8E93 |
| 主文字 | #000000 | #FFFFFF |
| 背景淡字 | #E5E5EA | #1C1C1E |

"完成"用主文字色实心，"未完成"用次要色描边。

**字体**：用系统字体，不打包字体文件。数字开启 `tnum`（等宽数字）。**不用宋体，不做仿古元素**。

**图标库**：
- 统一 1.5px 单线条，圆角端点，转成 VectorDrawable 内置
- 训练类：卧推、深蹲、硬拉、推举、划船、下拉、弯举、臂屈伸、飞鸟、腿举、跑步、步行、默认
- 饮食类：鸡蛋、牛奶、蛋白粉、鸡肉、牛肉、鱼、米饭、面、面包、燕麦、香蕉、蔬菜、默认
- **自动匹配**：用一张关键词表做包含匹配，例如"卧推"或"bench"对应卧推图标，"奶"或"奶昔"对应牛奶图标。按关键词长度优先匹配，都匹配不上就用默认图标

**动效**：
- 弹簧动画，柔和，不过度回弹
- 页面切换：淡入加轻微上移
- 按压：缩小到 96% 再回弹
- 不用墨滴涟漪，改为按压时轻微降低透明度
- 系统开启"移除动画"时，所有动画改为直接切换

**震动**（强度跟随设置，系统关闭触感反馈时不震动）：

| 档位 | 场景 |
|---|---|
| 轻 | 完成一组、打勾 |
| 中 | 完成一个动作 |
| 重 | 打卡开始 |
| 节奏（短、短、长） | 今天全部完成 |

## 11. 验证方式

- 每个里程碑：`./gradlew testDebugUnitTest connectedDebugAndroidTest` 全部通过，再在真机上按完成标准走一遍
- 热量引擎手算样例：男、75kg、175cm、30 岁、日常活动 120 kcal、12:00、已完成卧推 4 组（每组 8 kcal）
  - BMR = 1698.75
  - 均匀部分 = (1698.75 × 1.2 + 120) × 0.5 = 1079.25
  - 总消耗 = 1079.25 + 32 = 1111.25 kcal
- 年龄：把 Clock 调到明年 1 月 1 日，确认年龄 +1
- 导入导出：用 §6 的示例 JSON 往返一次，比较前后条数
