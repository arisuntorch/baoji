# 薄肌（baoji）饮食与训练计划

薄肌是一个 Android 健身记录 App。用户在「训练」页或「饮食」页左上角点「导入」，粘贴或选择一个 JSON 文件，App 就会生成每周的训练模板或每天的饮食打卡清单。

这个 skill 让你做到两件事：

1. **书写**：把用户口头描述的安排，变成一份 App 能直接导入的 JSON。
2. **理解**：读懂别人给你的薄肌 JSON（导入文件或 App 导出的备份），解释它在 App 里会变成什么样，并能修改、合并、排错。

先读完本文件。需要动作或食物关键词的完整表格时再读：

- `references/training.md`：训练计划的字段细节、动作关键词与肌肉对照、kcalPerSet 估算
- `references/diet.md`：饮食计划的字段细节、食物关键词、常见食物营养参考
- `references/backup.md`：App 导出的备份文件（`"type": "backup"`）怎么读，怎么转回导入格式
- `examples/`：可以直接导入的完整示例
- `scripts/validate.py`：校验脚本，规则和 App 内的校验器一致

## 1. 两种文件，一个外壳

训练和饮食是**两个独立的文件**，不能写在一起。每个文件最外层都是一个对象，并且必须有：

```json
{ "app": "baoji", "type": "training", "version": 1 }
```

- `app` 固定为 `"baoji"`
- `type` 为 `"training"` 或 `"diet"`（`"backup"` 是 App 导出的备份，只读不写，见 `references/backup.md`）
- `version` 固定为整数 `1`

### 训练计划（type = training）

```json
{
  "app": "baoji",
  "type": "training",
  "version": 1,
  "daily": [
    { "name": "步行通勤", "kcal": 120 }
  ],
  "plans": [
    {
      "name": "上肢",
      "days": [1, 4],
      "exercises": [
        { "name": "卧推", "sets": 4, "reps": [6, 8], "weight": 60, "kcalPerSet": 8 }
      ]
    }
  ]
}
```

| 字段 | 必填 | 类型与规则 |
|---|---|---|
| `daily` | 否 | 每天固定的日常活动（通勤、走路上课），每天都计入消耗。没有就省略 |
| `daily[].name` | 是 | 非空文字 |
| `daily[].kcal` | 是 | 数字 ≥ 0，每天消耗的千卡 |
| `plans` | 是 | 训练日模板数组，至少写一项 |
| `plans[].name` | 是 | 非空文字，同一文件内不能重复 |
| `plans[].days` | 是 | 整数数组，元素只能是 1–7，**1 = 周一 … 7 = 周日**。没被任何计划占用的日子就是休息日 |
| `plans[].exercises` | 是 | 动作数组，顺序就是 App 里的训练顺序 |
| `exercises[].name` | 是 | 非空文字，要包含动作关键词（见第 3 节） |
| `exercises[].sets` | 是 | 整数 ≥ 1（不能写 `4.0`） |
| `exercises[].reps` | 是 | 整数 ≥ 1，或区间 `[最少, 最多]`，要求 1 ≤ 最少 ≤ 最多 |
| `exercises[].weight` | 是 | 数字 ≥ 0，单位**公斤**，可以有小数；徒手写 `0` |
| `exercises[].kcalPerSet` | 是 | 数字 ≥ 0，每完成一组计多少千卡 |

### 饮食计划（type = diet）

```json
{
  "app": "baoji",
  "type": "diet",
  "version": 1,
  "targets": { "protein": 150, "carbs": 220, "fat": 60 },
  "meals": [
    { "name": "鸡胸肉", "amount": 200, "unit": "g", "protein": 46, "carbs": 0, "fat": 3 }
  ]
}
```

| 字段 | 必填 | 类型与规则 |
|---|---|---|
| `targets` | 否 | 每日营养目标（克）。写了就 `protein`、`carbs`、`fat` 三个都要写，都是数字 ≥ 0 |
| `meals` | 是 | 每天固定要吃的项目，至少写一项 |
| `meals[].name` | 是 | 非空文字，同一文件内不能重复（同一食物出现在不同餐次要区分，如 `"早餐鸡蛋"`、`"练前鸡蛋"`） |
| `meals[].amount` | 是 | 数字 ≥ 0 |
| `meals[].unit` | 是 | 非空文字：`"g"`、`"ml"`、`"个"`、`"份"`、`"根"`… |
| `meals[].protein` / `carbs` / `fat` | 是 | 数字 ≥ 0，是**这一项按这个数量吃下去的总克数**，不是每 100 g 的含量 |
| `meals[].kcal` | 否 | 数字 ≥ 0。不写时 App 按 `4×蛋白 + 4×碳水 + 9×脂肪` 计算 |

## 2. 书写计划的流程

1. **问清楚**（缺什么问什么，不要一次问一长串）：
   - 训练：每周练几天、哪几天、器械条件、当前各动作大概用多重、目标（增肌/减脂/力量）、有没有每天固定的通勤步行。
   - 饮食：体重和目标、每天大致吃什么、几餐、有没有忌口。
   - 用户不想回答时，按常见水平给一个合理估计，并在 JSON **之外**用一两句话说明哪些数字是估计的。
2. **按第 1 节的结构写 JSON**，动作名和食物名带上关键词（第 3 节）。
3. **自检**（第 5 节清单），能运行脚本时用 `scripts/validate.py` 校验。
4. **输出**：
   - 每个文件只输出**一个** ```json 代码块，不要在 JSON 里写注释（JSON 不支持 `//`、`/* */`）。
   - 用户同时要训练和饮食时，分成两个代码块。
   - 代码块外简短说明：一周怎么排、哪些值是估计的、导入时选「合并」还是「替换」。

### 写训练计划的要点

- 一套 `plan` = 一种训练日（如「上肢」「下肢」「推」「拉」「腿」）。同一种训练日一周练两次，就写一个 plan，`days` 填两天，**不要**复制两份。
- 建议同一天只放一套 plan。同一天放了多套时，App 会把它们的动作都列在当天。
- `reps` 用区间表示双进阶：App 会记住用户上次做到的次数，当上一次训练**每一组都做满了区间上限**，动作会被标上「加重」提示。因此区间是进阶目标，不只是描述；力量向常用 `[3,5]`、`[5,6]`，增肌常用 `[6,8]`、`[8,12]`，孤立动作常用 `[12,15]`。
- `weight` 写**工作组**重量。哑铃动作写单只哑铃重量，史密斯/器械写器械上的读数，并在说明里告诉用户你的约定。
- **不要**把跑步、走路、步数写成 `exercises`。临时有氧由用户在 App 里用「＋ 加练」记录；每天固定的走路通勤写进 `daily`。
- `kcalPerSet` 不需要很精确，按 `references/training.md` 的估算表填。

### 写饮食计划的要点

- `meals` 是用户每天要逐项打勾的清单，按吃的顺序排列。
- 所有 `meals` 的营养素加起来应接近 `targets`（建议各项误差在 ±10% 以内），这样全部打勾正好达标。写完要自己加一遍。
- 营养素是**总量**：200 g 鸡胸肉填蛋白约 46，不是每 100 g 的 23。
- 只在你有更准确的热量（如包装标注）时才写 `kcal`，否则省略让 App 计算。
- 营养目标的常见起点（仅供参考，不是医疗建议）：蛋白质 1.6–2.2 g/kg 体重，脂肪 0.8–1 g/kg，剩余热量给碳水。

## 3. 名字决定图标和肌肉图（重要）

App 按名字里的**关键词**匹配：

- **训练动作** → 图标 + 训练页人体图上要标色的肌肉
- **食物** → 图标

匹配规则：名字转成小写后做**子串匹配**；多个关键词都命中时，**最长的关键词胜出**，所以「腿弯举」匹配腿弯举（腘绳肌）而不是「弯举」（二头），「罗马尼亚硬拉」匹配罗马尼亚、「蛋白粉」匹配蛋白粉而不是「蛋」。不含任何关键词也能导入，只是显示默认图标、人体图不标色。

最常用的动作关键词：卧推、飞鸟、深蹲、箭步/弓步、腿举、腿屈伸、腿弯举、硬拉、罗马尼亚、臀推、推举/肩推、平举、面拉、耸肩、划船、下拉、引体、弯举、臂屈伸/双杠、下压、卷腹、平板支撑、转体、山羊挺身、提踵。完整表格和每个关键词对应的主练/辅助肌肉见 `references/training.md`。

最常用的食物关键词：鸡蛋、牛奶、酸奶、蛋白粉、鸡胸、牛肉、鱼、虾、豆腐、米饭、面、面包、燕麦、红薯、香蕉、苹果、西兰花、坚果、咖啡、水。完整表格见 `references/diet.md`。

几个容易踩的坑：

- 英文 `press` 单独出现会匹配成**肩推**。写英文时用 `bench press`、`leg press` 这类完整短语，或者直接用中文名。
- 「腹」是关键词，「腹肌轮」会被当成卷腹类，这是对的；但「腹部拉伸」也会被标成腹肌。
- 「分腿蹲」在人体图上按深蹲计算（含「蹲」），图标是箭步。

## 4. 读懂一份计划（解释给用户）

拿到一份薄肌 JSON 时，按下面的方式翻译成人话：

1. **看外壳**：`type` 告诉你是训练、饮食还是备份。备份文件按 `references/backup.md` 读。
2. **训练文件**：
   - 用 `days` 拼出周课表：1 周一、2 周二、3 周三、4 周四、5 周五、6 周六、7 周日；没出现的日子是休息日。
   - 每个动作读作「名字 组数×次数 @重量」，例如 `{"name":"卧推","sets":4,"reps":[6,8],"weight":60}` = 卧推 4 组，每组 6–8 次，60 kg，每组都做到 8 次后加重。单个整数 `reps: 12` 等于 `[12, 12]`。
   - 当天训练消耗 = 完成的组数 × 各自 `kcalPerSet`，只算真正打勾完成的组。
   - 每日总消耗 = 基础代谢（Mifflin-St Jeor）× 1.2 + 所有 `daily` 的 kcal + 当天训练消耗。
   - 可以用 `references/training.md` 的肌肉表算出每块肌肉一周练了多少组（主练肌肉每组算 1，辅助肌肉每组算 0.5，这也是 App 人体图的算法），指出练得偏多或漏练的部位。
3. **饮食文件**：
   - 每项读作「名字 数量+单位：蛋白 x g / 碳水 y g / 脂肪 z g（约 N kcal）」。
   - 把所有项加总，和 `targets` 对比，指出差多少。
   - 每日摄入 = 用户当天打勾项目的 kcal 之和。
4. **导入后会发生什么**（用户常问）：
   - App 先校验，出错时报「第 N 行 + 原因」，例如 `第 12 行 reps 应为正整数或 [最少, 最多]，且最少 ≤ 最多`。按第 6 节对照修复。
   - 导入时用户选择**合并**或**替换**：
     - **合并**：按 `name` 匹配。同名的计划/动作/日常活动/食物会被更新，新名字会新增，**文件里没写到的旧项目原样保留**。同名动作会保留用户已练到的次数（夹在新区间内）。
     - **替换**：把当前所有训练模板（或所有饮食项）归档，再写入新的。
   - 饮食文件里写了 `targets` 才会改营养目标；没写就保持原目标。
   - 已经记录过的历史（打过勾的组、吃过的饭、体重、日记）不会因为导入而改变。
   - 想**改名**时要提醒：合并模式下改名等于「新增一项 + 旧项保留」，想去掉旧名字要用替换。

## 5. 输出前自检清单

- [ ] 最外层有 `"app": "baoji"`、正确的 `"type"`、`"version": 1`
- [ ] 训练：每个动作五个字段齐全：`name`、`sets`、`reps`、`weight`、`kcalPerSet`
- [ ] 训练：`days` 只用 1–7；`sets` 是整数；`reps` 区间最少 ≤ 最多
- [ ] 训练：跑步、走路没有写进 `exercises`
- [ ] 饮食：每项六个字段齐全：`name`、`amount`、`unit`、`protein`、`carbs`、`fat`
- [ ] 饮食：营养素是总量；加总接近 `targets`
- [ ] 同一文件里 `plans` 的名字不重复，`meals` 的名字不重复
- [ ] 数字没有引号和单位（`60`，不是 `"60"` 或 `"60kg"`）
- [ ] 没有注释、没有末尾多余的逗号、没有 `NaN` / `Infinity`
- [ ] 动作名和食物名含关键词

能运行命令时：

```bash
python skills/baoji-plan/scripts/validate.py plan.json
```

脚本输出 `ERROR` 的项 App 一定会拒绝；`WARN` 的项能导入，但多半不是用户想要的（没匹配到关键词、营养加总偏离目标、某个计划没排日子等）。

## 6. 常见导入报错与修复

| App 报错 | 原因 | 修复 |
|---|---|---|
| `JSON 语法错误` | 多余逗号、注释、中文引号 `“”`、漏了括号 | 去掉注释和末尾逗号，引号全部用英文 `"` |
| `最外层必须是对象 { }` | 最外层写成了数组或多个对象 | 用一个 `{ }` 包住整份文件 |
| `type 应为 "training"，实际是 "diet"` | 在训练页导入了饮食文件（或反过来） | 到对应页面导入，或改 `type` |
| `xxx 缺失` | 必填字段没写或写成 `null` | 补上字段 |
| `xxx 应为整数` | `sets` 写成 `4.0`、`"4"` | 写成 `4` |
| `xxx 应为数字` | 数字加了引号或单位 | 去掉引号和单位 |
| `xxx 不能小于 0` / `不能小于 1` | 负数，或 `sets` 为 0 | 改成合法范围 |
| `reps 应为正整数或 [最少, 最多]…` | 区间写反、写成 `"6-8"`、三个元素 | 写成 `[6, 8]` |
| `days 应为 1–7 组成的数组` | 写了 `0`、`"周一"`、`[1-3]` | 写成 `[1, 2, 3]` |
| `plans 里有重名项「…」` / `meals 里有重名项` | 同名 | 改名区分 |
| `app 必须是 "baoji"` / `不支持的 version` | 外壳写错 | 改成 `"baoji"` 和 `1` |
